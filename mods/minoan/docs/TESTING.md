# 游戏内验收清单

所有项目在交付时均**未实机验证**。请使用可删除的新测试档，先关闭其他Gameplay Mod；不要直接加载重要存档。模拟测试通过不等于这里通过。

## 1. 加载与数据库

- 在风云变幻选择界面找到米诺斯，进入地图；原版希腊仍正常可选。
- 检查 `Database.log`/`Modding.log`，确认没有 `no such table`、`no such column`、外键或重复键错误。
- 检查 `Lua.log` 出现 `[MNS] Loaded`，没有 `ERROR`。
- 特色圣地成本为同科技/市政条件下普通圣地的约50%，大预言家点仍是普通圣地配置。
- 检查三个泛滥平原类型、地热、火山额外相邻；火山原有山脉相邻叠加。
- 检查区域模型、领袖场景、城市旗帜；美术占位不得导致加载失败。

可在FireTuner适当的Gameplay脚本上下文调用 `MNS_Diagnose(玩家ID)`。它只是查询并输出诊断，不会召唤灾害。

## 1.1 开局头衔和出生倾向（Alpha 4）

- 远古开局米诺斯建立首城后，应额外有1个可用总督头衔；不是已经替你任命。其他文明对照不加点。
- 未花点存读档、花完后存读档、建第二城、换总督、丢失/重获城市均不再发。晚时代开局只比原生多配置的数量。
- `StartingGovernorTitles` 改0/2分别新开档验证关闭/额外2点。
- 实际数据库应有米诺斯 `FEATURE_VOLCANO` Tier 1、三种泛滥平原 Tier 3，其他文明记录不变。
- 同一地图设置多次随机开局比较偏好效果；不要将一次好出生当作所有地图都保证。核对所选地图起点脚本是否读取火山地貌偏好。本Mod未加入地形生成或移动开局单位逻辑。
- `VolcanoStartBiasTier=0` 新开档只移除火山偏好；不影响泛滥平原。旧地图不会重新选址。

## 2. 专属总督（Alpha 4）

先关闭自动灾害，在标准速度新开米诺斯测试档；不要加载 Alpha 1/2/3 存档。

1. 打开原版总督界面，逐个核对七位姓名/肖像/基础技能/晋升树：只出现一套，不应同时有两位同名平伽拉等。不能只数 SQL 行数。
2. 面板启动时会输出 `[MNS GOVERNORS] appointment filter: PASS/FAIL`。FireTuner 在 `MNS_Panel` UI 上下文运行 `MNS_CheckGovernors()` 可重新检查；失败时保留具体 original/minoan 布尔值，不要继续正式档。
3. 分别任命平伽拉、马格努斯、梁等；每位用一个从未驻扎的新城市验证：指派后第一回合不生效，目标第二回合原生能力开始生效。**检查真实科文/砍伐/建造者效果，不只看面板倒计时。** 在指派当回合的计数口径也写入测试记录。
4. 同时观察 `MNS_GovernorEstablished`（Gameplay：`MNS_Diagnose(playerID)`，UI：`MNS_CheckGovernors()`）：就位前应无值/0，就位后应>0。灾害庇护与奖励只能在原生已就位时触发，不能提前。
5. 把已就位总督从A城调去从未驻扎的B城：A城标记和庇护应撤销，B城等待原生就位后获得。再换成同城另一个未就位总督、取消指派、间谍使总督中立化、占领/丢失城市，分别验证标记正确撤销。**模拟测试没有证明引擎会这样更新。**
6. 阿玛妮仍能派往城邦；人口补偿与奖励只能在己方城市生效。原生梁效果在外国城邦是否激活必须另测，不能只看Lua标记。维克多也使用专属250强度，不单独保留原版速度。
7. 另开一个其他文明的对照档：原版七位仍可用且速度不变，专属类型不能招募；奥斯曼易卜拉欣、秘密结社没有被克隆/提速。原版已有特色替换的第三方 Mod 需单独检查。
8. 调任中与已就位各存一次档，退出重载，确认技能/标记/名额不重复，不因读取旧 `MNS_Assignment` 而提前庇护。
9. 把配置改为 `125` 后新开对照档，应只改变米诺斯专属总督；其他文明不变。250目标2回合的映射和所有游戏速度仍需实测，不能从测试夹具推算。

本实现是每个新类型只替换一个原类型，不采用一个新总督替换七人的写法。已有开发资料提示替换限制，故必须验证七对都生效。出现14位总督或只有第一对替换时，诊断必须报错，本版不自动消耗/返还头衔修补名单。

## 3. 每种灾害分别验证

火山、洪水、森林火、雨林火、沙尘暴、暴风雪分别测试；**龙卷风不在召灾池中**。

1. 暂时关闭自动灾害，在庇护城市准备正常建筑、一个本来已被掠夺的建筑、一个有旧城防损伤的区域、改良设施及已被掠夺的改良。
2. 灾害前记录人口、城防、建筑/改良状态和城内信仰产出。
3. 使用祭司，检查原生灾害**确实发生在指定起点**，不是其他随机位置。
4. 人口由Lua补偿；结构必须由原生梁效果在结算时免伤，**不允许用自动修复判定通过**。关掉人口补偿脚本进行结构单独对照；旧损坏不应变好。森火/雨林火直到恢复结束都要观察。单位仍可能受伤。
5. 换无总督城市，灾害应正常造成损失且不给本能力科文。
6. 再测一场完全由游戏引擎自然发生的灾害，确认前置快照事件在Gameplay伤害之前执行。
7. 森火蔓延多个回合，确认重复回调不重复给奖励；评估保守5回合冷却是否符合你的体验。
8. 边境洪水/风暴同时影响不同玩家或不同城市时，按真实购地归属归城，不能用“最近城市”代替。

火山 `NamedVolcano` 与位置、洪水 `NamedRiver` 与位置之间的原生语义必须实际确认。目前有显式Location和河流编号，但**未实现通用命名火山ID解析**；若引擎要求该字段，不应猜测或跳到随机火山。先关闭对应事件类型并修正适配器。

### 3.1 肥地白名单与反例

- 分别验证12条明确事件有合法目标、正确动画与原生收益；概率事件多次观察，森林/雨林火记录恢复后的最终收益，不要求每次必加。
- 雨林必须触发 `RANDOM_EVENT_JUNGLE_FIRE`，不得给雨林塞入森林火；燃烧/恢复中不允许重启火灾。
- 只剩无林草地时，自动灾害应显示跳过，神谕祭司无合法目标；**不能退回龙卷风、陨石、彗星**。
- 保持末日先知开启，重复自动与神谕祭司施法，确认普通路径绝不进入彗星。再用末日先知在战争中单独确认原功能保留。
- 检查 `*_TRIGGERED`、第三方“名字含FLOOD的彗星”、带正值收益的未知事件均不入池；这部分已做模拟拒绝测试，进游戏核对候选日志。
- 晚期气候达到停止洪水/风暴肥力的阶段后，此类不再召唤；`MNS_Diagnose` 应报告候选减少，不能为保持频率而生成不肥地灾害。
- 水坝/巨浴池与有总督/无总督各做对照。没有改全球减灾规则，不应声称100%满额增产。
- 有天启模式/其他灾害Mod时，区分是本Mod召唤，还是它们自己的原生事件；本版未全局封禁彗星或海平面变化。

### 3.2 原生结构防护专项

逐个总督（不额外晋升强化材料）验证：任命前、未就位、已就位、调出、中立化。分别观察正常/旧损坏建筑、区域、改良、城墙和城市血量。

给米诺斯梁再点原版强化材料，确认没有重复绑定/失效问题；另一个文明的梁必须保持原版晋升要求。`ProtectionEnabled=0` 新开档不应获得本Mod额外结构防护，但原版梁自己的晋升仍保留。

若原生效果在副本上无效，本次不会再自动修好结构。这是未通过验收，不是“看起来没损失就算通过”。

## 4. 知识储备

- 城市40信仰/回合：默认入库20科学+20文化，不扣信仰余额。
- 当前科技剩15，至少5留到下一科技；文化独立测试。
- 不选择研究路线时奖励保留；存档退出读入后仍存在。
- 已有储备后触发尤里卡/鼓舞，再换研究路线，检查没有重复/丢失。
- 小数信仰多次奖励应累计，不应每次向下取整。
- 同一事件同城重复回调不重复付；不同受灾城各自最多一次。
- 全部科技/市政完成后不报错；重复未来科技/市政另测，当前没有专门适配其重复完成标志。
- 检查 `GetCulturalProgress` 在Gameplay是否可用；不存在时余额应该留下并报诊断，而不是偷偷走可能丢溢出的方案。

## 5. 祭司与彗星

- 不足信仰、未解锁、没有完整峰顶圣所、城市中心有平民占位：不给单位，不扣费。
- 神谕祭司2次，使用后移动归零，下回合可用剩余次数；读档保持剩余次数。
- 对敌/中立土地、战争外目标、战争迷雾目标、超距离目标发起请求：不扣次数，不产生灾害。
- 当前数据库无彗星时末日先知不可购买，不能以普通流星雨代替。
- 第1/2/3只末日先知分别3000/4500/6000；把前一只送掉不回退价格。
- 末日先知彗星双击确认；确认后真实彗星动画、原生撞击及毁城效果另行验证。
- 彗星不付科文、不保护被命中的敌方城市；首都/城邦/奇观目标需单独测试原生限制。
- 购买出来的原版宗教实例可能还有原版操作；验证它们不会制造角色属性、次数或免费单位漏洞。

## 6. 停止条件

下面任一项出现，不应继续使用正式档：重复/缺失总督、其他文明总督被修改、原生就位标记不能随调任/中立化撤销、灾害落在非指定起点、灾害请求长期未完成、保护回滚战争/造开拓者人口、原生接口抛错、重复科文、无费用重复祭司、存档属性无法恢复。

先关 `AutoDisastersEnabled`，保留施法前存档和 `Database.log`、`Modding.log`、`Lua.log`，定位调用。不要拿“看到了动画”当成完整结算成功。
