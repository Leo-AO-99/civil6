## 先看实现边界

代码、操作面板、配置及本地测试已写入本目录，但以下差异不能忽略：

| 设计项 | 当前实现 |
|---|---|
| 米诺斯文明、米诺斯领袖 | 独立数据库条目；肖像、颜色、图标借用希腊/伯里克利，没有复制其文明能力 |
| 峰顶圣所 | 替代圣地，默认50%成本，复制普通圣地功能并新增相邻；通过 ArtDefs 与 .dep 引用原版圣地模型及战略视图，未制作独立模型；新引用的实机显示待确认 |
| 每2–3回合灾害 | 每个米诺斯玩家独立计时，仅从12条肥地事件白名单中尝试一次；没有合法起点就跳过，不回退其他灾害。与神谕祭司共用同一筛选 |
| 开局总督点 | 默认开局额外1个，由玩家自行任命。原生一次性奖励，不按城/回合重复发 |
| 出生倾向 | 火山 Tier 1，三种泛滥平原 Tier 3；不造火山，不保证固定距离必有火山 |
| 总督2回合就位 | 新建七个米诺斯领袖专属内部类型，一对一替换七位原版总督，沿用原名、肖像和晋升；原生 `TransitionStrength=250`，目标2回合。原版条目不改。整套替换和实际就位时序仍需实机验证 |
| 城市免灾 | 七位专属总督绑定梁的原生结构防护；Lua **只补受灾人口**，不再保存或修复建筑/区域/城防/改良。原生防护在新总督上的实际生效与人口回调时序仍需实测 |
| 按信仰返科文 | 使用受灾城市每回合信仰，不扣储存信仰；独立科文倍率；持久化余额和去重记录 |
| 防止溢出浪费 | 只向当前研究补足所需进度，剩余留在存档属性。没有选科技/市政就先储存；接口不可用也不丢弃余额 |
| 森火去重 | 同事件ID同城只付一次，并有默认5回合城市森火冷却；**没有实现跨事件ID的完整火灾血缘追踪**，长时间蔓延仍可能冷却后再给一次，另一场独立火灾也可能被冷却挡住 |
| 神谕祭司/末日先知 | 采用原版传教士/使徒实例和模型，附加脚本角色及次数；在城市信仰购买列表购买，选中祭司后在单位操作区点击祭司按钮选择目标。没有左侧常驻面板。**不是新增ArtDef的两套原生UnitType**，购买扣费与原生宗教操作仍需实测 |
| 彗星 | 只在当前数据库确实存在彗星事件时允许购买，不会用普通流星雨或假伤害替代。资料片/模式未加载相应数据时不可用 |
| 联机/AI | 本版仅面向单人，联机/热座会停用脚本。AI可触发自动灾害，尚未编写祭司主动使用AI |

上一轮设计讨论中的“完全能做”“一定不会溢出”等表述不是已经通过引擎验证的承诺。本版本把能写出的逻辑落地，并把原生接口与时序依赖明确留在验收清单里。

## 我想改数值，在哪里改？

**只改 [`Config/Balance.sql`](Config/Balance.sql)。** 每一项旁边都有注释，`Value` 外的单引号保留。不要修改已安装游戏自己的数据库或游戏文件。

例如：

```sql
('StartingGovernorTitles', '1'), -- 开局额外总督头衔；0关闭
('VolcanoStartBiasTier', '1'),    -- 火山倾向：1强、5弱、0关闭
('FloodplainStartBiasTier', '3'), -- 泛滥平原辅助倾向
('HolySiteCostPercent', '50'),   -- 圣地成本50%
('AutoMinTurns', '2'),
('AutoMaxTurns', '3'),           -- 每2～3回合额外尝试一次
('ScienceRewardPercent', '50'),  -- 一次性科学 = 本城每回合信仰 × 50%
('CultureRewardPercent', '50'),
('MinoanGovernorTransitionStrength', '250'), -- 专属总督原生强度，目标2回合
('OracleFaithCost', '400'),
('ProphetFaithCost', '3000'),
```

| 参数 | 默认 | 含义 |
|---|---:|---|
| `StartingGovernorTitles` | 1 | 开局额外头衔，非负整数；0关闭，不自动任命 |
| `VolcanoStartBiasTier` | 1 | 火山出生倾向，1最强、5最弱、0关闭 |
| `FloodplainStartBiasTier` | 3 | 三种泛滥平原出生倾向，1～5或0关闭 |
| `HolySiteCostPercent` | 50 | 相对于加载时普通圣地基础成本的百分比；保留区域成长成本规则 |
| `VolcanoBonusFaith` | 2 | 每格火山**额外**信仰相邻；原有山脉相邻仍会叠加 |
| `GeothermalBonusFaith` | 2 | 每格地热裂缝额外信仰相邻 |
| `FloodplainBonusFaith` | 1 | 每格三类普通泛滥平原额外信仰相邻 |
| `AutoDisastersEnabled` | 1 | 0关闭本Mod额外灾害，不关闭游戏原生灾害 |
| `AutoMinTurns / AutoMaxTurns` | 2 / 3 | 每位米诺斯玩家的尝试间隔，最小值至少1 |
| `AutoFirstTurn` | 8 | 最早开始回合；头衔需自己任命，想延后灾害可改30或更高 |
| `AutoPreferProtected` | 1 | 优先从庇护城市找起点；不存在时会选其他己方土地 |
| `FireEnabled / FloodEnabled / VolcanoEnabled` | 1 | 森林及雨林火／河流洪水／已有普通火山的开关；自动与神谕祭司共用 |
| `StormEnabled` | 1 | 两类陆地肥地风暴的总开关，不含龙卷风与飓风 |
| `DustStormEnabled / BlizzardEnabled` | 1 / 1 | 沙尘暴／暴风雪分别开关；也受 `StormEnabled` 控制 |
| `MinoanGovernorTransitionStrength` | 250 | 仅米诺斯领袖专属七位总督的原生过渡强度，目标2回合；不是直接的回合数 |
| `ProtectionEnabled` | 1 | 0关闭本Mod新增原生防护、人口补偿和受保护城市奖励。影响SQL绑定，改后重新加载数据库；不取消原版梁自己已点出的晋升 |
| `ScienceRewardPercent` | 50 | 科学一次性奖励倍率，100表示一倍本城回合信仰 |
| `CultureRewardPercent` | 50 | 文化一次性奖励倍率，可和科学不同 |
| `RewardCityTurnCap` | 1 | 同城每回合奖励次数上限；0关闭回合上限，事件去重仍在 |
| `RewardRequiresSanctuary` | 0 | 1要求受灾城已有完整且未损坏的特色圣地；0不要求 |
| `FireRewardCooldownTurns` | 5 | 森火跨ID重复奖励的保守冷却 |
| `OracleFaithCost / OracleCostIncrease` | 400 / 0 | 内政祭司首只价格/每购买一次涨价 |
| `OracleCharges / OracleRange / OracleMoves` | 2 / 2 / 3 | 次数、施法距离、回合移动力 |
| `OracleUnlockCivic` | `CIVIC_THEOLOGY` | 神学解锁；空字符串表示不设市政门槛 |
| `ProphetFaithCost / ProphetCostIncrease` | 3000 / 1500 | 第一只3000、第二只4500、第三只6000……销毁单位不重置价格 |
| `ProphetCharges / ProphetRange / ProphetMoves` | 1 / 3 / 2 | 默认一次使用后消失 |
| `ProphetUnlockCivic` | `CIVIC_COLD_WAR` | 冷战解锁 |
| `ProphetEnabled` | 1 | 0禁用末日先知购买；其彗星始终是独立手动对敌技能，绝不加入普通召灾池 |

**改完需要重新加载Mod，区域/解锁/成本等改动建议新开档。** 不能承诺所有SQL修改都能安全应用到已有存档。不要同时启用本Mod的两份拷贝。

## 开局奖励与火山出生倾向（Alpha 4）

默认开局额外1个总督头衔，不自动任命特定总督。使用 `MODIFIER_PLAYER_ADJUST_GOVERNOR_POINTS`，参数 `Delta`，`RunOnce=1`、`Permanent=1`，仅绑定米诺斯领袖。玩家建立首城后自行任命/派驻。没有按城发放、每回合发奖或读档重新发奖的 Lua 回调。

这是开局奖励，不是每座城的奖励。设计上读档、建第二城、换总督都不会再领；一次性状态、晚时代开局的实际领取数量仍须游戏内验收。改 `StartingGovernorTitles=0` 不建立这项奖励，改成2则额外2点。不要在旧档中途加Mod来领取，升级版本和调参请新开档。

火山偏好从原来的 Tier 3 提高为 Tier 1，泛滥平原保留 Tier 3。使用原生 `StartBiasFeatures` 数据入口，**没有重写地图起点算法**。只让支持相应地貌偏好的地图脚本尝试优先选择已有火山区域；不生成火山、不传送开拓者、不赠送地块，不保证首都3格内/贴脸必有火山。0表示本Mod不插入对应偏好，不是引擎的第0级。自定义、真实出生点地图可能忽略偏好；本包尚未验证默认地图对火山偏好的实际处理，不能把SQL行存在当成生成效果已经生效。

## 普通召灾：只要肥地，不要毁地图

**适用范围：本 Mod 每2～3回合的自动灾害，以及神谕祭司的祈灾。** 不修改全局原生事件频率或其他 Mod；玩家主动启用天启模式时，其自身末日事件依然可能发生。该规则不是“整个游戏永远不会出彗星”的承诺。

| 允许类别 | 具体事件ID（`RANDOM_EVENT_`前缀） | 目标与收益 |
|---|---|---|
| 河流洪水 | `FLOOD_MODERATE`、`FLOOD_MAJOR`、`FLOOD_1000_YEAR` | 已有泛滥平原与合法河流；原生粮食/生产力概率增产 |
| 普通火山喷发 | `VOLCANO_GENTLE`、`VOLCANO_CATASTROPHIC`、`VOLCANO_MEGACOLOSSAL` | 已有普通火山；保留火山土及原生增产，不凭空造火山 |
| 森林／雨林火 | `FOREST_FIRE`、`JUNGLE_FIRE` | 分别匹配森林、雨林，保留燃烧→恢复→增产，不能对已燃烧/恢复中的地块重启火灾 |
| 沙尘暴 | `DUST_STORM_GRADIENT`、`DUST_STORM_HABOOB` | 沙漠／沙漠丘陵；原生粮食/生产力概率增产 |
| 暴风雪 | `BLIZZARD_SIGNIFICANT`、`BLIZZARD_CRIPPLING` | 冻土、雪地及其丘陵；原生粮食概率增产 |

**排除：** 所有陨石/流星雨、彗星、海平面上升、太阳耀斑、核事故、干旱、龙卷风，以及未逐条审核的第三方灾害。飓风虽有肥地收益，本版沿用陆地召灾范围，不加入池中。也不按名称通配加入 `*_TRIGGERED` 单位触发版本；部分版本与正常灾害的肥力数据不同。

筛选是“具体 ID 白名单 + 预期原生 EffectOperatorType + 实际加载的 `RandomEvent_Yields` 中存在正值粮食/生产力 + 地形检查”，不是只排除名字里有 `COMET` 的黑名单。遇到缺表、没有正值增产、负产出或毁地类操作符就不入池。最后提交 `ApplyEvent` 前再次检查：只有末日先知角色才有进入独立彗星路径的权限，自动调度与神谕祭司都没有。

**晚期气候：** 读取 `GetSeverityForLastSeaLevelEvent()`，对照已经达到的 `SEA_LEVEL` 事件中 `HaltsFloodFertility` / `HaltsStormFertility` / `FertilityRemovalChance`。已停止肥地的洪水/风暴不再选择；读取接口不可用时保守跳过这两类，仍可选火山/森火。此接口与时序还需实机验证；不修改全球气候，也不会逆转已发生的气候变化。

**“能肥地”不等于每次必定即时增产。** 原生概率、火灾恢复回合、水坝/巨浴池等减灾条件和后续气候变化仍由游戏处理，不人为把增产概率改成100%。火山土会改变地貌，火灾也会改变森林状态；这里禁止的是把可用地块砸成坑、变成海或凭空生成山等永久毁图事件，不是禁止正常的肥沃化地貌过程。

**末日先知不删除：** 保留之前约定的后期手动对敌彗星技能，需战争、可见性、距离和确认，不参与自动/神谕祭司抽取，也不返钱或返科文。

('MinoanGovernorTransitionStrength', '250'), -- 默认目标2回合
```

这是原生过渡强度，不是 `Turns`。不要填 `2` 期待两回合；`125` 可用作目标4回合的对照配置。回城残留就位进度、游戏速度或其他 Mod 会影响实际表现，以原生界面和能力生效的实测为准；本版不承诺一个通用公式能精确得到任意回合数。非正整数/非数值配置会报数据库错误，不会静默变为零。

**庇护也改为跟随原生已就位状态。** 原生需求 `REQUIREMENT_CITY_HAS_GOVERNOR_WITH_X_TITLES`（至少1头衔、`Established=1`）控制一个非永久城市属性，Gameplay 与 UI 读取同一状态。不再用“指派后过两回合”的 Lua 计时模拟就位，也不依赖 Gameplay 中可能没有暴露的 UI 总督对象。

原先 `ProtectionEstablishTurns`、`GlobalGovernorSpeedOverride`、`GlobalGovernorTransitionStrength` 均已移除。旧的 `MNS_Assignment` 存档属性不再读取。**这不是旧存档迁移：Alpha 1 存档必须新开，不能把已有的原版总督自动转成新类型。**

本机实测 `GovernorReplaces` 行存在，但 `CanEverAppointGovernor` 仍同时允许原版和专属总督。因此通过原生 GovernorPanel 扩展隐藏米诺斯的七个原版待招募候选，其他领袖不受影响；旧档已经任命的原版总督保留管理入口，避免头衔投入后无法操作，新档应只见一套。UI 首次加载核对专属版本可用性并写入日志；`MNS_CheckGovernors()` 的 PASS 不代表引擎自动排除了原版。具体实机验收见 [TESTING.md](docs/TESTING.md)。

**兼容性边界：** 共享晋升定义会继承其他 Mod 对这些定义的修改；复制型条目以本 Mod 加载时的模板为准。硬编码原版总督 ID 的第三方脚本不一定识别专属类型。多行替换是否全部生效、`Established` 对调任/中立化的处理、城市属性能否及时撤销仍需引擎验证，不能拿 SQL 行数或模拟测试代替。

## 安装

Alpha 1/2/3 升级到本版请新开可丢弃的测试档；不迁移旧灾害快照。需要《风云变幻》规则集；彗星还要求当前游戏加载对应事件内容。我们没有随包分发Firaxis的资料片数据，也没有自动开启天启模式。

1. 将整个 `minoan` 文件夹复制到你的《文明 VI》用户目录下 `Mods/`；也可解压打包产物里的 `MinoanDisasters` 文件夹。
2. 确认布局是 `Mods/MinoanDisasters/MinoanDisasters.modinfo`，**不要多嵌套一层目录**。
3. 在“额外内容 → 模组”启用 `Minoan Disasters — 米诺斯天灾文明 [Alpha]`，创建风云变幻新游戏，选“米诺斯”。
4. 先按 [TESTING.md](docs/TESTING.md) 验收；只看见文明选择项并不代表Lua机制已正常加载。

### Windows 手动安装

运行Mod不需要 Python、Lua 命令行或 ModBuddy，也不需要编译。

1. 完全退出游戏，解压 `MinoanDisasters-alpha4.zip`，复制里面的 **`MinoanDisasters` 文件夹**，不要把ZIP直接放进Mods。
2. 按 `Win+R` 输入 `shell:Personal` 打开Windows实际“文档”，进入 `My Games/Sid Meier's Civilization VI/Mods`。`Mods` 不存在可新建，但先确认选中的是已有游戏用户数据目录；OneDrive可能重定向“文档”。
3. 最终必须能直接找到 `Mods/MinoanDisasters/MinoanDisasters.modinfo`。旧版移到Mods目录外备份，不能仅改名后仍留在Mods里；不要放进Steam游戏安装目录。
4. 启用本Mod，单人新建**风云变幻**规则集，选择米诺斯。首次测试先关闭其他修改总督/出生点/灾害的Mod，不必开启天启模式来测试普通肥地灾害。
5. 首城建好后打开总督界面，检查额外1个可用头衔以及七位总督只出现一套。没看到火山不能单独证明加载失败：偏好不是保证。

安装目录结构：

    ├── Data/
    ├── Gameplay/
    ├── UI/

```

改数值时修改**已安装在Mods中的** `Config/Balance.sql`；修改仓库源文件后要重新复制安装。退出游戏再编辑，重启并新开档。

若找不到Mod，检查层级和实际文档位置。若开始游戏返回主菜单，保留同一用户目录下 `Logs/Database.log`、`Logs/Modding.log`、`Logs/Lua.log`（以实际生成的文件为准）。本版未实机测试，请先用可丢弃的新存档。

Windows常见用户目录为：

```text
文档/My Games/Sid Meier's Civilization VI/Mods/
```

用户目录可能被OneDrive重定向。macOS/Linux的发行渠道和用户目录不同，请以本机已存在的Civ VI用户数据目录为准；将Mod放在其 `Mods/` 子目录，不要覆盖Steam安装目录里的原版文件。

### 两种祭司怎么用

**神谕祭司：** 仅召唤上面的肥地白名单。城市建好峰顶圣所，达到神学后，选中城市，在原版“信仰购买”列表的“米诺斯祭司”栏目购买。选中该祭司，点击单位操作区的祭司按钮，再通过“上一格/下一格”选择范围内**当前可见的己方合法土地**，点击祈灾。目标窗口默认关闭，切换单位后自动关闭。使用一次扣一份脚本次数并耗尽移动力。地形决定可选灾害，多个符合时随机，不保证每次必定触发你偏爱的类型。

**末日先知：** 达到冷战后在城市信仰购买列表购买。选中祭司并点击单位操作区的祭司按钮，选择**当前可见且属于交战玩家的陆地**。彗星需要再次点击确认，默认一次后消失；不会返还科文。不自动宣战，不能炸盟友/和平玩家。起点所有权校验不代表灾害范围永远不会波及边境外其他玩家。

购买需点击信仰列表中专门命名的“神谕祭司”或“末日先知”。普通传教士/使徒没有 `MNS_Role` 属性，不能获得这些技能。两个条目使用原生购买列表的控件，但价格、扣费与脚本角色仍由 Gameplay 校验。两类单位当前用原版宗教单位实例做脚本变体，不保证与改变传教士/使徒的其他Mod兼容。

如果末日先知条目提示“当前规则集没有加载彗星灾害”，购买不会扣费。开启已拥有的相应天启内容后可测试；**并不宣称在未启用天启的普通规则下已经实现了彗星数据移植**。

## 科文储备与去重

储备、已结算事件、城市当回合计数和森火冷却保存在玩家的 `MNS_Knowledge` 属性内，随游戏存档持久化。不会存在外部临时文本里。

每次先将奖励加入储备，再向当前正在研究的科技/市政补充最多所需的进度。不替你选择研究路线。超额保留到下一项；API不可用则保留余额并记录错误。写进度前存一条待确认记录，之后读取结果结算，避免科技完成事件重入而重复消费。

目前没有“导出储备”功能，也不把这部分文化同时转换为城市扩地文化/旅游业。调高比例不会直接改变每回合显示的科文产出。

## 庇护的范围：结构原生防护，只有人口由Lua补偿

`Data/Governors.sql` 给七位专属总督的 `GovernorModifiers` 绑定原版
`REINFORCED_INFRASTRUCTURE_PREVENET_STRUCTURAL_DAMAGE`。
它使用原生 `EFFECT_ADJUST_PREVENT_STRUCTURAL_DAMAGE`，保留总督上下文，不挂到普通建筑或文明级对象上。原版梁和其他文明的共享晋升定义完全不改；此处没有给埃及洪水免疫或巨浴池效果叠加一遍。

加载时检查原版效果、`COLLECTION_OWNER` 和 `Prevent` 参数存在且符合预期；缺失/被其他Mod改变时报告数据库错误，**不会悄悄改回全结构修复**。

原生防护的目标范围为建筑、区域、改良设施、城市和城墙血量。**本包未运行游戏：尤其要验证该修正器直接绑定 `GovernorModifiers` 时的就位/调任时序，以及森火、火山的实际覆盖。** SQL存在不等于已经验证免伤，不能把测试夹具当游戏引擎。

`Gameplay/MNS_Protection.lua` 现在只记录城市身份、人口和奖励用的信仰，不读取结构状态。灾害完成后只对实际受影响且仍受庇护的同一城市补回人口差额。未受影响的城市、丢失/被删除城市、已失去总督庇护的城市不补人口，人口增长也不扣回。

**Lua没有任何结构修复兜底。** 若实测建筑/改良仍损坏，应报告原生防护接入缺口，而不是让脚本修好后误判成功。不复活单位、不重建彗星删除的城市、不防海平面淹没；森火和火山的地貌及肥沃化仍由原生处理。

人口补偿仍依赖灾害伤害之前的Gameplay快照与真实受影响范围。没有事前快照时不拿回合初人口猜测；使用原生事件和本Mod主动事件分别测试。阿玛妮派在城邦时人口补偿与奖励不生效；原生结构效果对外国驻扎的范围还需实测，不能凭Lua自家城市判断推断原生效果范围。

原生日志已出现灾害及一次科学/文化奖励入库，但旧自动事件曾因无法匹配完成回调而永久阻断后续调度。本轮除同一事件类型和起点外，也接受原生灾害范围包含请求地块的确认（例如同河洪水的另一回调坐标）。自动事件到下回合仍未确认时，记录 unconfirmed 并解除等待，沿用已安排的 2～3 回合间隔，不立即重试，也不伪造成功。`[MNS DISASTER]` 记录 attempted、confirmed、unconfirmed、skipped、failed、rejected，计数保存在玩家 `MNS_DisasterAudit`；attempted 不等于灾害成功。

手动施法仍保留未确认锁，次数只在原生完成事件匹配后扣除；若一直等待，请保留日志并回到施法前存档，避免连点。当前新确认规则与模型显示仍需实机核对。另有两个已知缺口：本局自然事件未观察到 Gameplay 事前快照；文化进度 getter 在 Gameplay 不可用时，文化奖励保留在储备中，尚未兑现。
